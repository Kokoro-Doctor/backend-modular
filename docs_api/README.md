## Notes

### Phone Number Formats

All phone numbers are normalized to E.164 format. Accepted formats:

- `+919587733170` (with country code)
- `9587733170` (10 digits, assumes +91)
- `919587733170` (12 digits, adds +)

### Date Formats

- Dates: `YYYY-MM-DD` (e.g., `2025-01-15`)
- Times: `HH:MM` (24-hour format, e.g., `10:00`, `14:30`)

### Base64 Encoding

For file uploads, ensure content is base64-encoded. Example tools:

- Online: https://www.base64encode.org/
- Command line: `base64 -i file.pdf`

### Authentication

Most endpoints require authentication via JWT token in `Authorization` header:

```
Authorization: Bearer <jwt_token>
```

Admin / service-specific headers:

- **`x-admin-key`** — Auth (delete-account), Booking (test-subscription)
- **`x-hospital-api-key`** — Hospital raw data ingestion on Medilocker Lambda (`/hospital/upload`, presign-upload, confirm-upload)
- **ABHA Lambda** — `GET /abha/profile` and `GET /abha/card` require `Authorization: Bearer` (Kokoro JWT). ABDM tokens are stored in AbhaAccounts and resolved server-side. Optional JWT on create/login verify links the ABHA record to `kokoro_user_id`. HIP linking (`POST /abha/link/*`), bridge admin routes, and `GET /abha/transactions` require Kokoro JWT. Async HIP calls return `request_id` and are tracked in AbdmTransactions (poll via `GET /abha/transactions`). Inbound ABDM callbacks use fixed paths `/api/v3/hip/token/on-generate-token` and `/api/v3/link/on_carecontext`; correlate on `response.requestId` in the callback body.
- **Hospitals Lambda** — staff routes use `Authorization: Bearer` (JWT from `POST /hospitals/login`). CRUD routes in this repo do not validate `x-admin-api-key` (protect at API Gateway if required).
